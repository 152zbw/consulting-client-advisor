# 交付沟通

## 启动与阶段汇报

启动时核实目标、交付、双方投入、决策人、反馈窗口与验收依据。建议沟通节奏须与项目相称，不新增合同义务。

阶段汇报采用：本阶段结论 → 证据与限制 → 对客户的影响 → 建议选择 → 需要确认的事项。清楚区分完成、已提交、待反馈、已确认；材料提交不等于验收。

解释专业成果时，先讲客户将用它决定什么，再讲方法。遇到质疑先核实数据、口径、样本和解释，确有错误则纠正；不要用术语压过客户。

## 配合不足与延误

说明缺少什么、原约定依据、对哪些工作造成何种影响、已有缓解措施、建议动作。区分我方原因、客户依赖与共同问题；不在证据不足时归责。

表达示例：“目前还缺[资料]，这会影响[分析/交付]。我们建议先推进[可独立部分]，同时请双方确认资料提供安排，之后再更新受影响的排期。”具体期限没有确认就不编造；不自动宣布延期生效。

我方延误：承认已核实事实，说明影响、纠正及恢复方案；是否费用减免或赔偿需要适用授权，不自行承诺。

## 新增需求与升级

先问新增事项要解决的实际使用问题，核对现有成果能否满足，再依责任规则分类。额外讲解、增做分析、新增数据、增加实施辅导分别评估，不以名称相似判断同范围。

重大分歧时汇总事实、双方立场、影响、可选方案及需要谁决定；建议由项目负责人协调或升级。对外不揣测“客户在甩锅”，内部也只陈述可观察行为。
